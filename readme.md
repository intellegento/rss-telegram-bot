# RSS Telegram Bot

Бот присылает в чат новости из ваших источников (RSS, ленты RSSHub, публичные Telegram-каналы через RSSHub, Binance), в которых встречаются ваши ключевые слова.

## Установка

1. Клонируйте репозиторий:
```bash
git clone https://github.com/your-username/rss-telegram-bot.git
cd rss-telegram-bot
```

2. Создайте виртуальное окружение и активируйте его (проверено на Python 3.12 и 3.13):
```bash
python3.12 -m venv .venv
source .venv/bin/activate  # для Linux/Mac
# или
.venv\Scripts\activate  # для Windows
```

3. Установите зависимости:
```bash
pip install -r requirements.txt
```

4. Создайте файл `.env` из шаблона и заполните значения:
```bash
cp .env.example .env
```

| Переменная | Назначение |
|---|---|
| `TELEGRAM_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather), обязательно |
| `DATABASE_URL` | PostgreSQL (Neon): `postgresql+psycopg://user:password@host/dbname?sslmode=require`. Схемы `postgresql://` и `postgres://` (так их передаёт интеграция Neon в Vercel) приводятся к `postgresql+psycopg://` автоматически. Обязательно: без неё бот завершается с ошибкой. Подходит и pooled-адрес Neon (`...-pooler...`) |
| `BINANCE_API_KEY` | ключ Binance (сейчас не используется, можно оставить пустым) |
| `BINANCE_API_SECRET` | секрет Binance (сейчас не используется, можно оставить пустым) |
| `TEST_DATABASE_URL` | отдельная БД для тестов, в том же формате. Тесты её очищают, поэтому это не должна быть рабочая БД |

`config.py` только читает эти переменные из окружения и `.env`, секретов в нём нет.

## Миграции

Схема БД создаётся только миграциями Alembic. Перед первым запуском и после обновления кода:

```bash
alembic upgrade head
```

Новая миграция после изменения моделей в `database.py`:

```bash
alembic revision --autogenerate -m "описание изменения"
```

Проверьте сгенерированный файл в `alembic/versions/` и примените его через `alembic upgrade head`. Откат последней миграции: `alembic downgrade -1`.

## Запуск

```bash
python main.py
```

Бот работает в режиме polling. Каждые 5 минут выполняются два шага (`pipeline.py`):

- `collect()` опрашивает активные источники, на которые подписан хотя бы один пользователь, сохраняет новые записи в `posts` и удаляет посты старше 14 дней;
- `deliver()` отправляет каждому пользователю до 10 подходящих по ключевым словам постов, опубликованных после его подписки на источник (если у поста нет даты — полученных после неё). Отправленное записывается в `deliveries`. Если пользователь заблокировал бота, он помечается неактивным.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не обращаются к Telegram и внешним источникам: всё подменено моками. Тесты с БД используют `TEST_DATABASE_URL`: перед прогоном применяют миграции, после каждого теста очищают таблицы. Если `TEST_DATABASE_URL` не задан или совпадает с `DATABASE_URL`, эти тесты пропускаются.

## Функциональность

- Личные подписки: каждый пользователь видит и удаляет только свои источники. Запись источника общая: если на одну ленту подписаны несколько человек, она опрашивается один раз
- Источники: RSS-ленты (в том числе RSSHub и публичные Telegram-каналы через RSSHub) и Binance Announcements
- Фильтрация новостей по ключевым словам без учёта регистра (по заголовку и описанию)
- При подписке старые новости не присылаются: приходят только посты, опубликованные после неё (без даты публикации — полученные после неё)
- Управление источниками и ключевыми словами через меню

## Лимиты бесплатной версии

| | Бесплатно | Премиум |
|---|---|---|
| Ключевые слова | 5 | без ограничений |
| Источники | 2 | без ограничений |

Значения заданы константами `FREE_KEYWORDS_LIMIT` и `FREE_SOURCES_LIMIT` в `config.py`. При превышении бот сообщает, сколько использовано из скольких, и что лимит снимает премиум. Премиум действует, пока `users.premium_until` в будущем; способ его оформления появится позже.

## Команды

- `/start` - Запустить бота
- `/help` - Показать справку
- `/keywords` - Показать ваши ключевые слова
- `/add` - Добавить ключевое слово
- `/remove` - Удалить ключевое слово
- `/sources` - Показать список источников
- `/add_source` - Добавить источник
- `/remove_source` - Удалить источник

## Безопасность

Секреты хранятся только в `.env`, который не включается в репозиторий. Шаблон со списком переменных — `.env.example`.
