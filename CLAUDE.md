# rss-telegram-bot: правила для агента

## Продукт
Telegram-бот: пользователь подписывается на источники (RSS, ленты RSSHub, публичные Telegram-каналы через RSSHub) и задаёт ключевые слова. Бот присылает в чат новости, где встречаются эти слова.
Бесплатно: 5 ключевых слов и 2 источника. Премиум (подписка Telegram Stars или ключ суперрежима): без ограничений.
X API и AI-сводки пока НЕ реализуем. Но не закрываем дорогу: у источника есть поле type, а новости хранятся в БД.

## Стек
- Python, python-telegram-bot.
- PostgreSQL в Neon, SQLAlchemy, миграции Alembic.
- Продакшен: Vercel (webhook + эндпоинт сбора, который вызывает внешний cron).
- Локально: режим polling для разработки.

## Правила работы
- Минимум кода, который решает задачу этапа. Никаких функций, абстракций и настроек сверх задачи.
- Меняй только то, что требует задача. Не переформатируй и не «улучшай» соседний код. Замеченный посторонний мусор перечисли в отчёте, но не трогай.
- Убирай только то, что стало лишним из-за твоих изменений.
- Если задача неясна или есть несколько толкований, остановись и задай вопрос, а не выбирай молча.
- Для каждой правки, которую можно проверить кодом, сначала тест (pytest), потом исправление.
- Внешние сервисы (Telegram, RSS, RSSHub) в тестах подменяй моками. Реальные запросы к ним только по явной просьбе.
- Сверяйся с актуальной документацией библиотек и сервисов, а не с памятью. Версии фиксируй в requirements.txt.
- Один логический шаг = один коммит с понятным сообщением на русском или английском.

## Безопасность
- Никогда не выводи и не коммить значения секретов. Все секреты только из переменных окружения.
- .env.example содержит имена всех переменных без значений.
- Не пушь в удалённый репозиторий без явной просьбы.

## Отчёт в конце каждого этапа
1. Что сделано (по пунктам, с файлами).
2. Результат каждой проверки из чек-листа этапа: пройдено / не пройдено и почему.
3. Что осталось нерешённым, какие вопросы и допущения.
4. Что нужно сделать человеку вручную.
